# Features

Git Graph is a desktop git history viewer built with Avalonia and modelled on the [Git Graph](https://github.com/mhutchie/vscode-git-graph) extension for VS Code.

## Commit Graph & History

- **Commit graph**: Every branch, remote branch, and tag is drawn on a colored lane, with uncommitted changes shown as a dashed row at the top.
- **History, filtering & search**: Filter by branch, show or hide remotes, find commits by message, author, hash, or branch name, and scroll down to load older commits. The filter button opens fields to show only commits by an author, from a recent period, touching a file or folder, or adding/removing code (`git log -S`); the graph keeps its lane lines through a path filter. The find box also accepts text filters (`author:ana path:src/ code:"var x" since:month tiles`, then Enter) to populate the fields and highlight matches.
- **Branch & tag labels**: Each ref is rendered as a pill filled with its lane color and a branch, tag, or cloud icon. A local branch and its remote tracking copies on the same commit share one label (`main │ origin`), and the checked-out branch is bold. The target button next to the branch jumps to `HEAD`. Right-click a label to check out, merge, rename, or delete a branch, set its upstream, delete a remote branch from its remote, or push a tag.
- **Highlight a branch**: Right-click a branch or tag label and choose **Highlight its commits** to fade every loaded commit that does not lead to it, making it easier to trace one line through a busy graph. Press `Esc` or choose **Clear** to stop.
- **Contributors**: The chart button opens contributor insights for the current branch: daily activity heatmap, commits per week, and each contributor's commit count, share, lines added/removed, and weekly activity over a chosen period, sorted by commits, additions, or deletions (merge commits excluded, `.mailmap` respected).

## Diffs, Review & File History

- **Diffs & full diff window**: Inspect files changed by a commit, the working tree, or between any two commits (`Ctrl+click` the second commit). Diffs are computed with [DiffPlex](https://github.com/mmanela/diffplex) with word-level highlights inside modified lines, and support both unified and side-by-side views. Double-click a file (or right-click it) to compare the whole file in a full diff window: bands across the middle connect each change to its counterpart, `F7` / `Shift+F7` jump to the next or previous change, an overview map beside the scrollbar shows every change, the caret's line displays its counterpart at the bottom with an inline blame note (author, date, and commit), text selects across lines and copies, and unchanged stretches fold into GitHub-style expander rows. Syntax highlighting matches VS Code's themes. Under **View**, diffs can ignore whitespace and toggle line wrapping. A button above the diff opens the file in VS Code, and changed images show before/after previews side by side with dimensions.
- **Review comments**: Comment on any line of a commit's diff: hover a line in the details panel and click the comment button next to its line number, or right-click a line in the full diff window. Comments appear inline under their lines (edit or delete your own), the full diff window marks commented lines and provides a **Comments** list beside the code, and the commit list shows comment counts. Comments are stored in git notes (`refs/notes/gitgraph-comments`), so **Fetch** brings in everyone's comments and **Push**, **Publish**, and **Sync** push yours, merging concurrent comments across clones.
- **File history & blame**: Right-click a changed file (or a file in a folder tab), or click the clock button above a diff, to open the file's history across renames together with each commit's diff. The **Blame** tab shows the commit, author, and date that last changed each line; clicking a commit opens it in the history view.

## Working Tree, Staging & Git Operations

- **Stage & commit**: Select the uncommitted changes row to view changes grouped into staged changes, changes, and merge conflicts. Stage, unstage, or discard a file from its row buttons or group heading (`Ctrl+click` / `Shift+click` for multi-select, arrow keys, `Space` to stage/unstage, `Delete` to discard), or act on individual hunks via each hunk's **Stage**, **Unstage**, and **Discard** buttons. To stage, unstage, or discard specific lines within a hunk, click their line numbers in the unified diff before using the hunk buttons. Write the commit message on the **Commit** tab and commit with the button or `Ctrl+Enter`; check **Amend last commit** to replace the previous commit and reload its message. When nothing is staged, **Commit** offers to stage all changes first.
- **Stash**: Stash uncommitted changes (with or without untracked files) from the uncommitted row's context menu or the **Repository** menu. Each stash appears in the graph above its base commit with a `stash@{n}` label; select it to inspect saved changes (including untracked files), or right-click it to apply, pop, drop, or create a branch from it. **Repository → Pop latest stash** restores the newest stash.
- **Graph actions & interactive rebase**: Right-click a commit or branch to merge it into the current branch, cherry-pick it, rebase the current branch onto it, revert it, or reset the current branch to it (`soft`, `mixed`, or `hard`). `Shift+click` a second commit to select a range and cherry-pick (oldest first) or revert (newest first) all non-merge commits in between. **Interactive rebase from here** opens subsequent commits in a list where you can pick, reword, squash, fixup, or drop commits and drag (or `Alt+Up`/`Down`) to reorder them; uncommitted changes are stashed and restored automatically, and branches with pushed commits are flagged as needing a force push. When a merge, cherry-pick, revert, or rebase hits conflicts, a banner above the graph offers **Continue** and **Abort**, and conflicted files appear under uncommitted changes with options to keep either side, open in VS Code, or stage once resolved.
- **Fold staged changes into an earlier commit**: Right-click a commit and choose **Fold staged changes into this commit** to fold what is currently staged into that commit (via a fixup commit and autosquash rebase) while keeping unstaged changes and showing which commits will receive new hashes or require a force push.
- **Undo & reflog**: **Repository → Undo last action** reverts the last commit, amend, checkout, merge, rebase, pull, or reset after explaining the exact effect (undone commit changes remain staged, and uncommitted changes are preserved); running Undo again redoes it. **Repository → Reflog** lists recent `HEAD` movements so you can create a branch from, check out, or reset to commits left behind by a reset or rebase.
- **Pull, push & auto-fetch**: The toolbar and sidebar show ahead/behind counts (`↓` / `↑`) against each branch's upstream. Click the indicator to **Sync** (pull then push) or **Publish** a branch without an upstream. **Repository** also provides **Pull**, **Push**, **Force push (with lease)**, and pull mode selection (merge, rebase, or git config). Repositories are fetched automatically in the background every 3 minutes (configurable or disabled under **View → Fetch automatically**); newly fetched commits show a notification and remain marked in the sidebar until opened, and fetch failures show a warning icon with the error in the tooltip.

## Repositories, Files, Code Navigation & Terminal

- **Repositories & worktrees**: The sidebar lists repositories discovered up to three levels deep from added folders, with **Add folder** and **Rescan** actions at the top and **Remove from list…** in each repository's context menu. Linked worktrees are listed under each repository; you can add a worktree from any commit or branch, open it in its own tab, or remove it, and commits checked out in another worktree are marked in the graph.
- **File browser & git states**: Click the folder button in a repository's toolbar or right-click a repository/worktree in the sidebar to browse its files in a tab or in a separate window. File trees color files and folders by git state (`M`, `A`, `U`, `R`, `!`, dimmed ignored files, and change indicators on parent folders), support **View → Compact folders**, and remember expanded folders, selection, and tree width. Files open in a read-only AvaloniaEdit viewer with VS Code syntax highlighting, `Ctrl+F` search, image previews, and an inline blame note on the caret's line.
- **Code navigation**: In a folder viewer, `F12` or `Ctrl+click` (`Cmd+click` on macOS) jumps to a definition, `Shift+F12` lists references, `Ctrl+F12` lists implementations, and `Alt+Left` / `Alt+Right` navigate history. `Ctrl+P` opens fuzzy file search, `Ctrl+T` searches symbols across the repository/folder index, and `Ctrl+Shift+F` runs `git grep` text search across all files (and nested repositories). C#, Go, Rust, Java, C, C++, Python, JavaScript, TypeScript, and Zig are parsed in-app with [tree-sitter](https://tree-sitter.github.io) and indexed into a local SQLite database in the background; other languages fall back to whole-word matching.
- **Embedded terminal**: Each tab includes a toggleable shell panel so you can run git or project commands in the active repository or folder without leaving the app.

## Customization & Layout

- **Keyboard shortcuts**: Defaults mirror VS Code where applicable (`Ctrl+B` sidebar, `Ctrl+J` details panel, `Ctrl+W` close tab, `Ctrl+PageDown`/`PageUp` and `Alt+1…9` for tabs, `Ctrl+K` chords). Open **File → Keyboard shortcuts** (`Ctrl+K Ctrl+S`) to search, record, reset, or remove bindings with conflict warnings.
- **Custom commands**: Configure shell commands under **File → Custom commands** to appear in commit, branch, file, and **Repository** menus. Placeholders `${sha}`, `${short}`, `${subject}`, `${branch}`, `${file}`, `${path}`, and `${repo}` are shell-quoted and also exported as `GITGRAPH_*` environment variables, with optional confirmation prompts and output dialogs.
- **Commit messages & avatars**: Commit bodies render as Markdown with clickable links. Author avatars load from GitHub (for GitHub noreply addresses) or Gravatar and are cached for a week, with fallback options under **View → Author avatars** (Gravatar generated sets, RoboHash, DiceBear using hashed addresses, or locally drawn identicons/initials). Network requests respect environment proxies and GNOME desktop proxy settings.
- **Layout & font size**: Toggle the sidebar (`Ctrl+B`), toggle or maximize the details panel (`Ctrl+J`), use preview tabs (single-click in the sidebar opens an italic preview tab; double-click keeps it open), and zoom all text and row heights with `Ctrl+=`, `Ctrl+-`, and `Ctrl+0` (**View → Font size**).

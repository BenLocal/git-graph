# Known pitfalls

> Non-obvious problems hit while building this project, and what fixed them.

- 2026-10-17 Snapshots: `grim` can't capture the screen on GNOME Wayland → the window renders itself with `RenderTargetBitmap` when `GITGRAPH_SNAPSHOT` is set (`src/GitGraph.App/Views/MainWindow.Snapshot.cs`). Separate windows such as dialogs are not captured.
- 2026-10-17 Fonts: the IBM Plex packages on npm / jsdelivr contain no TTF files (404) → take Mono from google/fonts and the static Sans weights from `cdn.jsdelivr.net/gh/IBM/plex@v6.4.0/IBM-Plex-Sans/fonts/complete/ttf/`.
- 2026-10-17 Repaint on theme change: Avalonia 12 `Control` has no `ActualThemeVariantProperty` to observe → custom-drawn controls subscribe to the `ActualThemeVariantChanged` event and call `InvalidateVisual()` (`Controls/GraphCell.cs`).
- 2026-10-17 In `LanePalette` the method name `Color` clashes with the `Color` type → use the full name `Avalonia.Media.Color.Parse`.
- 2026-10-17 Installed app had no icon: the window set no icon (`_NET_WM_ICON` missing, checked with `xprop -id <window>`), and the launcher entry pointed only at an SVG → the window now sets `Icon="/Assets/Icons/gitgraph-256.png"`, and `make install` installs PNGs into `~/.local/share/icons/hicolor/<size>/apps` with an absolute `Icon=` path. No SVG rasterizer is installed here, so `scripts/render_icon.py` redraws the icon with Pillow; Pillow's wide polylines break at joints, so strokes are stamped as dots.
- 2026-10-17 Blurry text and icons on GNOME at 125% scale: with `xwayland-native-scaling`, Mutter gives X11 clients Xft.dpi 192, so Avalonia renders at 2x, then Mutter shrinks the window to 1.25 and softens it (confirmed: `GetCurrentState` scale 1.25, app `RenderScaling` 2). Avalonia 12.1's native Wayland backend (`Avalonia.Wayland`, `UseWaylandWithFallback()`) renders at exactly 1.25. Under Wayland, `RenderTargetBitmap` at 1.25 renders parts of the tree at the wrong size, so snapshots stay at 1x unless `GITGRAPH_SNAPSHOT_SCALE` is set.
- 2026-10-17 Contributor line counts are slow: `git log --numstat` or `--shortstat` over vikunja's 16k commits takes ~10 s either way (git diffs every commit). The view shows commits from a fast log first and counts lines afterwards into a per-repository cache (`~/.local/share/GitGraph/stats/*.tsv`).
- 2026-10-17 Dock showed "Unknown" after switching to Wayland: Avalonia 12.1's Wayland backend never sends `xdg_toplevel.set_app_id` (checked with `WAYLAND_DEBUG=client`), so GNOME can't match the window to `gitgraph.desktop`. `Services/WaylandAppId.cs` finds NWayland's `XdgToplevel` in the window's platform impl by reflection and calls `SetAppId("gitgraph")` on open; every window and dialog does this.
- 2026-10-17 Correction to the Wayland note above: after trying both on GNOME at 125%, the user found X11 (XWayland) text sharper than the native Wayland backend, even though Wayland renders at exactly 1.25 (`preferred_scale(150)` with `wp_viewport`) and windows also get desktop-style text options (subpixel, slight hinting, aligned baselines). X11 is the default again; `GITGRAPH_BACKEND=wayland` opts in. Judge sharpness on the real screen: snapshots can't show it.
- 2026-10-19 Periodic fetch could stop for good → `git fetch` had no timeout, so one stalled connection (`GIT_TERMINAL_PROMPT=0` stops prompts, not hangs) kept the workspace's `_fetching` guard set and every later fetch was skipped, while failures were swallowed silently → `GitRepository.FetchAsync` now stops after `FetchTimeout` (2 min) and failures show as a CloudAlert icon with the reason in the sync tooltip.
- 2026-10-19 Staging one hunk failed on files with tabs → `DiffLine.Text` has tabs expanded for display, so a patch built from it doesn't match the file → `TextDiff.HunkPatch` takes each line from the original old/new texts by line number, and `git apply --recount` fixes the hunk counts.
- 2026-10-19 A path-filtered `git log` drew lanes to commits that aren't in the list → with path limiting, `%P` still prints the real parents; adding `--parents` rewrites them to the nearest shown commit (`GitRepository.GetCommitsAsync`). Author and date filters don't rewrite parents, so the graph drops lines to commits that aren't shown.
- 2026-10-19 A style selector naming `DiffText` never matched → `DiffText` overrides `StyleKeyOverride` (to `SelectableTextBlock` since 2026-10-23, before that `TextBlock`), so type selectors see that type; style it through a class (`SelectableTextBlock.code` for wrapping), and keep `TextWrapping` out of the templates, since a local value beats any style.
- 2026-10-19 Switching files in Changes was slow (0.3–0.9 s each) → TextMate colouring both versions of a C# file takes most of a second (git and the diff take tens of ms), and the diff waited for it → `ComputeDiffAsync` returns the diff uncoloured, `ColourAsync` adds colours afterwards through `DiffLineViewModel.ApplySyntax`, picking another file cancels it, and `SyntaxHighlighter` caches recent texts. Measure such things with a Stopwatch per stage before guessing.
- 2026-10-23 The running app held 100+ pipe fds with no git child alive → `Process.Dispose` doesn't close redirected streams read through `StandardOutput`/`StandardError` (only `BeginOutputReadLine` ones), so each `GitRunner` call leaves its stdout/stderr read ends open until the GC finalizes them. Bounded, not a leak (a forced GC dropped 116 to 10). Fixed: `GitRunner` disposes both streams (`GitRunnerTests`). Measured with a 100-run repro and `ls -l /proc/<pid>/fd`. In the same app, `dotnet-gcdump` showed 123 MB live of a 326 MB gen2: most of RSS was garbage waiting for a gen2 GC, and the largest live item was TextMate grammars (~70 MB of `Parser.Raw`, 2 registries, 9 grammars, bounded by languages opened).
- 2026-10-23 Memory leak hunt → a throwaway console app referencing `GitGraph.App.csproj` can drive the real app on X11 (`AppBuilder.Configure<App>().UsePlatformDetect().AfterSetup(...)`, `GITGRAPH_STATE` pointing at a copy of `.demo/state.json`), repeat actions, and check `WeakReference`s after `GC.Collect`. 15× each of the full diff, file history and blame windows, repo tab open/close, workspace switches, context menus, menu bar menus, combo boxes, tooltips and dialogs left nothing behind beyond Avalonia's per-control tooltip and menu popups. Unexplained: an instance used by hand for 6 hours held 35 `X11Window` and 49 `PopupRoot`, which scripted popups don't reproduce (unverified cause; next time take `dotnet-dump collect` and run `gcroot` on an `X11Window`).
- 2026-10-24 Synced diff editors didn't scroll → AvaloniaEdit 12's `TextEditor.ScrollToVerticalOffset` / `ScrollToHorizontalOffset` are no-ops (the editor's `VerticalOffset` stayed 0); setting `Offset` on the `ScrollViewer` in its template works (`CompareView.ScrollTo`). Also, `FoldingManager.Install` binds to the document the text area has at that moment, so install it after setting `Document` (or `CreateFolding` throws "Folding must be within document boundary").
